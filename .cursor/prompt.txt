### ПОЛНОЕ ОПИСАНИЕ КОНТЕКСТА ПРОЕКТА
* ТЕМА: Система управления автосалоном и прокатом автомобилей (Car Dealership System).
* СТЕК: Node.js, NestJS (TypeScript), Prisma ORM, PostgreSQL.
* ДОПОЛНИТЕЛЬНО: class-validator, class-transformer.
* БЕЗОПАСНОСТЬ: Проект пишется СТРОГО БЕЗ АВТОРИЗАЦИИ (все сущности и связи управляются через явные ID в REST API).

### ТРЕБУЕМАЯ АРХИТЕКТУРА СВЯЗЕЙ В БАЗЕ ДАННЫХ:
1. One-to-One (Один-к-одному): Car ➡️ CarDetails
   - У каждой машины (Car) есть один уникальный паспорт характеристик (CarDetails: VIN-код, цвет, объем двигателя). Характеристики зависят от машины и должны удаляться каскадно.
2. One-to-Many (Один-ко-многим): Showroom ➡️ Car[]
   - Есть автосалоны (Showroom), в каждом из которых может быть много машин. Машина жестко привязана к одному автосалону. При удалении салона машины удаляются каскадно.
3. Implicit Many-to-Many (Неявная многие-ко-многим): Car[] ⬅️➡️ Feature[]
   - У машин есть опции комфорта (Feature: "Автопилот", "Подогрев руля"). Одна опция может быть у многих машин, у одной машины может быть много опций.

### НАШ ПЛАН РАБОТЫ ПО ЭТАПАМ:
* Этап 1: Проектирование файла schema.prisma и создание миграции.
* Этап 2: Создание CRUD для независимых сущностей (Showroom и Feature) + DTO валидация.
* Этап 3: Создание модуля центральной сущности Car (с вложенным созданием CarDetails и связыванием Feature через DTO).
* Этап 4: Реализация пагинации в списках и безопасных методов поиска/удаления.
* Этап 5: Реализация обновления связей Many-to-Many через оператор `set` в Patch-запросах.
